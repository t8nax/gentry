Gentry ведёт задачу по флоу проекта: сценарий состоит из этапов, у каждого этапа есть исполнитель, выход и инструкция. Состояние задачи хранит Gentry, и меняется оно только командами `gentry`.

Программа: `<gentry>`. В командах ниже `gentry` — эта программа.

## Взятие задачи

1. Проверить, есть ли в копии задача: `gentry task show`. Если задача есть, перейти к разделу «Этап».
2. Узнать сценарий. Если оператор его не назвал, показать сценарии командой `gentry flow show` и спросить, по какому сценарию вести задачу.
3. По словам оператора сформулировать название — одну строку до 80 знаков — и постановку: что должно быть сделано и при каких условиях задача выполнена.
4. Записать поля `scenario`, `title` и `statement` в файл JSON инструментом записи файлов и взять задачу: `gentry task take --input <файл>`.
5. Отменённую задачу взять заново: `gentry task take --task <задача> --scenario <сценарий>`.

Если взятие отклонено, назвать оператору причину из отказа и сделать то, что предлагает отказ, только с его согласия.

## Этап

1. Прочитать постановку и решения оператора: `gentry task show --statement`. Прочитать этап: `gentry stage show`.
2. Если исполнитель этапа — оператор, попросить оператора выполнить этап. Закрыть такой этап только после его ответа, выход записать его словами.
3. Перед работой задать шаги этапа: `gentry step add`. Выполненный шаг отметить с проверкой: `gentry step done <номер> --check <как проверено>`. Снять шаг можно только с обоснованием: `gentry step drop <номер> --reason <обоснование>`. Шаг, снятие которого сужает постановку, снимается только по решению оператора.
4. Когда все шаги выполнены или сняты, закрыть этап выходом: `gentry stage exit`. Выход артефактом сначала сохранить: `gentry artifact save`. На развилке указать переход и обоснование. Пропустить этап можно только с обоснованием: `gentry stage skip`.
5. После перехода прочитать новый этап: `gentry stage show`.
6. То, что нужно учесть дальше, записать заметкой: `gentry note add`.

Возврат сверх предела отклоняется. В этом случае спросить оператора, разрешает ли он ещё один возврат, и записать ответ с разрешением: `gentry operator record --allow-return <узел>`.

## Решения оператора

Ответ оператора на вопрос по задаче записать решением оператора дословно, вместе с вопросом: `gentry operator record --input <файл>`, поля `question` и `answer`. Если у вопроса были варианты, добавить их полем `options`. Указание оператора без вопроса записать так же, без `question`.

## Правила

- Рамки задачи задают постановка и решения оператора. Расширять или сужать задачу можно только по решению оператора.
- Длинный текст передавать командам файлом JSON через `--input`, а не в аргументах.
- Вид команды и её полей смотреть в справке: `gentry <команда> --help`.
- О недостатке самого Gentry сообщить оператору и ничего не записывать.

## Закрытие

Когда сценарий пройден, закрыть задачу: `gentry task close`. Если закрытие отклонено из-за незакоммиченных изменений, показать оператору изменённые файлы и спросить, что с ними сделать.

Отменять задачу можно только по слову оператора, по скиллу `<skill:canceling-task>`.
